# Хронология наблюдений в Git

```sh
prowl scan --git-timeline --ml --format json -o git-history.json
prowl repo https://github.com/org/repo --git-timeline --format sarif -o git-history.sarif
prowl org github:org --git-timeline --ml --format json
```

`--git-timeline` включает `--history` и доступен для `scan`, `repo`, `org`. Локальный
`scan` читает Git текущего каталога; позиционные пути, stdin, `--staged` и `--since`
несовместимы с историей. Обычный `--history` без `--cross-file` сохраняет прежний быстрый сбор уникальных
объектов без хронологии. Репозитории для `repo` и `org` клонируются с полной историей.

В JSON у находки появляется `git`; в SARIF та же структура лежит в
`results[].properties.git`. По умолчанию этого поля нет. Значения секретов остаются
замаскированными, а baseline/fingerprint и live-верификация сохраняют свой контракт.

| Поле | Значение |
|---|---|
| `basis` | `detector_observations_first_parent` |
| `head` | Зафиксированный при начале сбора commit HEAD |
| `complete` | Достаточность покрытия для отрицательных выводов |
| `in_head` | Наблюдается в отслеживаемом пути дерева HEAD; поле отсутствует при неопределённости |
| `appearances` | Коммиты появления относительно первого родителя, включая повторное появление |
| `removals` | Коммиты прекращения наблюдения относительно первого родителя |

Коммит содержит hash, parents, имя автора, авторскую дату и дату коммита. Сообщение
коммита и email автора не включаются. Событие удаления дополнительно содержит
`introduced_in` и, когда даты позволяют, `exposure_seconds`: интервал между датами
коммитов появления и прекращения наблюдения. При обратном ходе часов длительность
не вычисляется. Это датировка истории Git, а не точное время публикации репозитория,
утечки или отзыва credential у провайдера.

Сбор включает все достижимые ветки и теги плюс зафиксированный HEAD. Для каждого
коммита сравнивается дерево с первым родителем; корень сравнивается с пустым деревом.
При merge событие означает изменение относительно первого родителя, а не первую
публикацию секрета во всём репозитории. События упорядочены по графу, не по датам:
даты коммитов могут идти назад. Переименование — удаление старого пути и появление
нового; содержимое gitlink/submodule не читается как файл родительского репозитория.

Каждая пара «путь + blob» сканируется один раз. Разные пути одного blob сохраняются;
обычная правка файла при сохранении того же значения не разрывает период. Находки
связываются по существующему fingerprint: тип + путь отчёта + полное значение.
Поэтому одинаковые значения в разных файлах имеют отдельные истории размещения;
общий HMAC-индекс связывает их отдельно. Все версии связываются до CLI dedupe,
`--verified-only`, baseline и ограничений отчёта. Для значений, попавших в отчёт,
учитываются также кандидаты до ML, allowlist и inline-прагм: подавление отображения
уже обнаруженного кандидата не превращается в событие удаления.

Хронология основана на распознавании кандидатов выбранным детектором. `removals`
означает прекращение наблюдения в поддержанном представлении файла, а не доказанный
поиск точных байтов во всех неизвестных форматах и не подтверждение отзыва ключа.
Изменение правил, названий переменных или поддерживаемых кодировок может изменить
наблюдения; результаты разных конфигураций нельзя считать одной непрерывной оценкой.
`in_head: true` не означает provider-confirmed live: для этого существует `verified`.

Shallow-клон, ошибка чтения, отмена и лимиты детектора/нормализации не подтверждают
отсутствие. Непрочитанная бинарная или контейнерная версия пути оставляет историю
неопределённой. Для архивов положительные попадания сохраняются; отсутствие отдельного
внутреннего файла в новом архиве не доказывается без полного сопоставления контейнера.
При неполной истории `complete: false`, события удаления скрыты, отрицательный
`in_head` отсутствует; положительный HEAD может быть подтверждён независимо.
Диагностики неполноты сохраняются в отчёте и дают CLI exit 2.

Чтобы ограничить стоимость отдельного режима, действуют пределы: 10000 коммитов,
1000000 записей изменения пути, 64 МиБ суммарных метаданных графа, 1000000 наблюдений
кандидатов и 10000000 шагов «находка × коммит». Размер blob ограничивает обычный
`--max-size`. Превышение не выдаётся за полный результат. Используются локальные
Git-объекты; external diff и textconv отключены. Режим не обращается к провайдерам,
пока отдельно не включён `--verify`.


## Составные credentials и ревизии

```sh
prowl scan --git-timeline --cross-file --verify --ml --format json
prowl repo https://github.com/org/repo --git-timeline --cross-file --verify --format sarif
```

С `--cross-file` используется полный tree каждого commit, поэтому неизменённый
primary сканируется повторно с companions именно этой ревизии. Граф и деревья
разделяют один captured список commit. Отдельный приватный logical fingerprint
связывает detection lifecycle; revision location IDs и provider verdicts сохраняют
свою раздельность. Формат `git` и `basis` остаются прежними. Разные verdicts одного
primary в двух commit не становятся appearance/removal событиями.

Lifecycle разрешается до `--verified-only`. Pre-filter observations не становятся
удалениями при скрытии кандидата, а provider invalid не доказывает отсутствие
primary в дереве. Проверки у провайдера выполняются сейчас, не на дату commit;
`git` описывает распознавание в Git, а `verification` — текущий ответ на tuple.

К графовым лимитам добавляются component budgets: 10000 выбранных tree entries
и 32 MiB raw bytes суммарно по всем ревизиям, не на каждый tree. Unborn без refs
даёт полный пустой scan, shallow не разрешает полный composite intake. Source
ошибки блокируют composite probes; дальнейшая неполнота детектора/разрешения
lifecycle сохраняется после уже выполненных валидных запросов и запрещает baseline
и отрицательные lifecycle выводы. [Полный контракт](Cross-File-Credentials.md).

Локальная matrix 1304/1304 + repo/org 386/386, real Git fixtures и owned loopback
provider; unit checks, race/min-Go/lint, шесть сборок, quality/corpus и fixed
performance gate обычного per-item pipeline проходят. Стоимость timeline acquisition
отдельно не измерялась. Hosted CI и реальный аккаунт этим не квалифицированы.
Evidence — `evidence/1.5.0-cross-file-timeline-20261116.json`.
