# Идентичность секретов и происхождение находок

В кандидате 1.5.0 восстановлена HMAC-идентичность отчётов из выпущенной 1.4.0.
Без ключа сохраняется прежний SHA-256 fingerprint. С ключом `secret_id` зависит
от логического значения; `fingerprint` также учитывает тип и исходный путь.
`identity_scope` обозначает ключ. `occurrence_id` учитывает источник, координаты,
неизменяемые метаданные и evidence; после разбора structured literals и
реконструкции он пересчитывается по исходным координатам.

```sh
prowl identity init -o ./private/identity.key
prowl scan ./src --identity-key-file ./private/identity.key --format=json
```

`identity init` без `-o` создаёт `$PROWL_HOME/identity.key`; такой ключ автоматически
используется последующими сканированиями. Отсутствие необязательного файла сохраняет
режим без ключа. Существующий неверный файл, оборванный symlink родительского каталога
или неверный явный путь завершают подготовку с кодом 2. Источник и отчёт при этом
не открываются. Создание исключительно: существующий файл не заменяется. Ключ —
ровно 32 hex-encoded байта; он не печатается. Менять ключ означает менять область
идентичности и keyed fingerprints baseline.

Unix-загрузчик отказывается от symlink, специальных файлов и открытых другим
пользователям прав; ограничивает чтение 256 байтами, сверяет открытый inode и не
блокируется на FIFO. Инициализация создаёт файл с правами 0600. Windows-сборки
проверены компиляцией; проверка Windows ACL остаётся отдельной релизной задачей.

HMAC нового локального индекса (`value_fingerprint`, private location identity)
сохраняет свой отдельный ключ и формат. Report identity его не заменяет.
Git timeline использует тот же keyed fingerprint, что и отчёт, включая наблюдения
до ML: подавление на экране не доказывает исчезновение значения в Git.

Provenance передаётся через контекст производителя до отправки Item в канал.
Поддержаны `blob`, `commit`, `digest`, `layer_digest`, `run_id`, `artifact_id`,
`source_url`, `source_map`, `original_source`, `git_index`. Неизменяемые идентификаторы
проверяются по формату; это не независимая проверка существования ревизии.
URL очищаются от userinfo, query и fragment; неподдерживаемые поля не экспортируются.
Значение provenance после очистки ограничено 2048 байтами, превышение отражает
неполноту результата. Не все источники пока заполняют все метаданные релиза.

```sh
python3 scripts/check_report_identity.py /path/to/prowl
```

Runner использует новый приватный `PROWL_HOME`, собственные временные ключи и
локальный Git-репозиторий. Он сохраняет отчёт, не включает live verification
и не изменяет установленный ключ пользователя. Пройдено 39/39 сценариев, а также
204/204 structured literals и 24/24 reconstruction. Полный Go suite, race,
минимальный Go 1.26.11, lint и шесть CGO=0-сборок проходят. Отчёт —
`evidence/1.5.0-report-identity-20261114.json`.

Это восстановление JSON Finding и Pipeline. Полный coverage envelope, свойства
SARIF и остальные контракты выпущенной базы остаются открытыми в TODO.
Матрица координат использует `--no-dedupe`: перенос `occurrences` при стандартном
объединении повторных находок ещё требуется восстановить отдельно из 1.4.0.
