# Локальные CLI-контракты перехода 1.4.0 → 1.5.0

Проверка 2026-11-15 сопоставляет два настоящих процесса CLI. Reference пересобран
из неизменённого `refs/tags/v1.4.0` (`f72ea02d0295e764bec5a32359240e77192073fc`)
на Go 1.27.4 с `CGO_ENABLED=0`. Это исходный тег, а не скачанный опубликованный
бинарник. Проверены все экспортированные файлы `tool/`, включая `go.mod` и
`go.sum`; зависимости reference не обновлялись.

Кандидат — чистая статическая сборка feature-коммита `fc44184`, SHA-256
`63066eb227c5f09d7ac647a7ea73dfd443f1407c59664791fd39e31053837759`.
Рабочие файлы `tool/` совпадают с main `1e4c8e2`: последующие изменения
касаются тестов, fuzz-seed и документации. Проверка не заменяет сборку
финального релизного артефакта.

Матрица прошла **190/190**, по 95 проверок на версию:

- 170 проверок общего поведения: короткие формы запуска, явный `scan`,
  граница `--`, help/version, stdin/файл JSON/YAML/TOML, UTF-16 LE/BE,
  `--ci` и приоритет явного `--fail-on` над конфигурацией, отказы конфликтующих
  source modes и неподдерживаемых worker stages. Логическое имя stdin
  может указывать на несуществующий вложенный путь: путь не открывается
  и не создаётся. В 24 парах literal-сценариев совпали type/path/line/col,
  optional UTF-16 поле и маскирование.
- 20 проверок расширения explicit-false. Тег 1.4.0 отвергает `--ci=false`
  и `--strict=false` как неизвестные флаги; кандидат поддерживает их.
  Неполный ввод всё равно возвращает 2 и не меняет существующий baseline.
  Это объявленное различие, а не 190 побитово одинаковых результатов.

Для настоящего терминального stdin используется `os.openpty`, вывод читается
через pipe. Запуск без аргументов и `scan` читают текущий каталог при PTY;
при piped stdin читают переданные данные. Проверены и pretty-, и JSON-вывод.
Существующие отчёты и baseline в негативных сценариях принадлежат только
этой проверке и остаются неизменными.

Оба бинарника запускаются с новым `PROWL_HOME` и OS network deny. Разрешённый
контроль делает один запрос к собственному loopback-серверу, тот же запрос
под sandbox блокируется и не достигает сервера. Действительность секретов
не проверяется. Исходные находки и полные выводы в evidence не сохраняются:
записаны коды выхода и хеши потоков.

Дополнительно прошли связанные Go-тесты CLI и `source`: foreign flags всех
18 command schemas, end-of-options, повторы и явные значения, вложенные
команды, generated help, precedence конфигурации, сохранность отчёта,
named stdin, его предел и отмена. Эти проверки не меняют рабочий код.

Воспроизведение на macOS:

```sh
PROWL_LIVE_TEST= python3 scripts/check_cli_upgrade_contract.py /absolute/reference /absolute/candidate
```

Runner требует `sandbox-exec`, запускает собственные процессы в новом
временном каталоге и ничего не публикует. Для Linux/Windows, опубликованных
архивов, полной области CLI remote-команд, ML/провайдеров, индекса и всех
остальных контрактов продукта это сравнение не даёт общего допуска.
Предыдущие квалификации L2 и verification-order остаются отдельными.
