# Прогресс стадий в терминале

Долгая команда показывает одну обновляемую строку в **stderr**, начиная примерно через
секунду. Условие — stderr является настоящим терминалом, `--quiet`/`--silence` не заданы.
Прогресс остаётся видимым, даже если stdout перенаправлен в файл, pipe или содержит
JSON/SARIF. Управляющие последовательности не попадают в stdout и файлы отчётов.
При перенаправлении обоих потоков или самого stderr индикатора нет.

Это поведение сохранено из `fb02f32`; проверки stdout и stderr проводятся раздельно.
`--log-format=json` также не отключает индикатор на терминальном stderr: такой stderr
предназначен для человека. Для машинного чтения логов следует перенаправить stderr;
при этом прогресс автоматически отключается.

Стадии: `listing repositories…`, `cloning repository…` / `cloning repositories…`,
`loading image…`, `scanning…` и `scanning and verifying…`. Последняя охватывает весь
Pipeline.Run, включая ожидание провайдера после закрытия входного канала.
Подпись loading image остаётся активной до завершения чтения слоёв, а не только до
возврата metadata из `source.Image`. Ленивое чтение может продолжаться после него.
Загрузка образа имеет приоритет над общим scanning label, пока поток ещё не закрыт.

Счётчик обозначает элементы и объём текста, переданные сканеру, а не сетевые байты,
число provider HTTP-запросов, подтверждённых секретов или процент завершения.
В подписи нет URL, пути, значения, redaction или тела ответа. `1 file` выводится
в единственном числе. Другие стадии восстанавливаются после окончания вложенной.

На узком экране строка сокращается под текущую ширину, последняя колонка остаётся
свободной. Logger сначала стирает показанную строку. Перед отчётом и выходом команды
индикатор останавливается и стирается, даже если отменённый source ещё завершает
свою работу. Поздний finish callback не закрывает уже закрытый канал и не стирает
строку новой стадии. Аналогично старый renderer не может стереть новый после join.

`TERM=dumb`, не-terminal character devices и legacy Windows console без уже
включённых VT-controls не получают progress controls. Команда не меняет режим консоли.
`--no-color` / `NO_COLOR` убирают цвета, но не запрещают обновление строки.
Windows runtime отдельно не квалифицирован; шесть релизных целей собираются с CGO=0.

## Проверки

```sh
python3 scripts/check_progress_contract.py /path/to/prowl
```

Реальный Unix PTY, независимые stdout/stderr, ширина 30 колонок, собственный Git clone
shim на локальном репозитории, docker-save tar через задержанный stdin и loopback
read-only verifier: **36/36**. Проверены режимы файла и pipe, чистый JSON/SARIF в stdout,
подавление прогресса, маскирование, отсутствие остатка строки в финальном экране,
отмена клонирования, image input и verification. Быстрые операции не мерцают.
Внешние provider/registry не вызывались. Матрица включена в CI `native-acquisition`.

Проходят full Go, CLI race, lint и Go 1.26.11. Существующие матрицы repository 99/99,
verdicts 49/49, source coverage 36/36 и гейт 1556/2094 / 57/982 сохранены.
Внешний CI и финальные образы в этих проверках не участвовали.
