# Сопоставление отчётов и проверка исправления

```sh
prowl correlate FIRST.json SECOND.json
prowl remediation-check BEFORE.json AFTER.json
```

Команды читают JSON envelope Prowl `schema_version: "1.4"` и выводят JSON в stdout.
Это версия протокола отчёта, а не продукта. Исходные файлы не изменяются; верификаторы
и сетевые источники не вызываются. Команды не требуют приватного identity key,
но все входные отчёты должны быть получены с одним report identity key.

## Корреляция

`correlate` группирует наблюдения по `secret_id` в одном `identity_scope`.
Идентификаторы должны быть каноническими lower-case hex; отчёты без ключевой
идентичности или с разными ключами отвергаются. Все сохранённые occurrences
участвуют в сопоставлении метаданных артефакта.

`relationship: same_secret_observed` означает равенство HMAC identity.
Совпадающие валидные `blob`, `commit`, `digest` или `layer_digest` дают ссылки
`shared_*_metadata` с идентификаторами поддерживающих occurrences. Это равенство
переданных метаданных; оно не доказывает направление распространения секрета.
На группу допускается 256 ссылок; превышение поднимает `links_truncated` и
`complete: false`. Неполный исходный отчёт также сохраняет неполноту результата.

## Наличие и сохранённый verdict

`remediation-check` рассматривает только секреты, наблюдавшиеся в BEFORE:

| Поле | Значения и смысл |
|---|---|
| `presence` | `present`: наблюдается в AFTER; `absent_in_scope`: не наблюдается в сопоставимом полном объёме; `inconclusive`: отсутствие не установлено. |
| `revocation` | `live`: сохранённый detailed verdict подтверждал работоспособность; `provider_rejected`: все имеющиеся текущие observations имеют verdict `invalid`; `not_checked`: достаточного detailed verdict нет. |
| `closed` | Всегда `false`: команда не подтверждает окончательное закрытие исправления. |

Наличие любого live occurrence сильнее rejected occurrence. Legacy boolean без
подробного verdict не подтверждает отзыв. Ошибки и unsupported/skipped не равны
отказу провайдера. Противоречивые boolean/detailed verdict, неизвестный статус
или некорректное время проверки отвергаются при чтении.

Данные о провайдере пересказывают **сохранённое** наблюдение из отчёта; повторной
проверки и оценки свежести здесь нет. Отсутствие ключа в AFTER не подтверждает
его отзыв. Ключ, оставшийся в исходниках с verdict `invalid`, всё ещё `present`.

Для `absent_in_scope` нужны одинаковые полные scopes и отсутствие фактического
подавления `filtered` в обоих отчётах. Одних command/pipeline/rules scopes
недостаточно: требуется известная область приобретённого локального источника
(filesystem/stdin/file-list/Git/mobile/image/agent). Unknown/remote scopes пока
не подтверждают отсутствие; их producer provenance остаётся отдельным аудитом.
Изменение detector revision, параметров источника или identity key может сделать
отчёты несопоставимыми.

## Границы чтения и коды возврата

Не принимаются явно раскрытые экспорты (`secrets_revealed`), finding context и
значения без ожидаемой формы маскирования. Проверка формы не аутентифицирует
происхождение отчёта и не доказывает правдивость произвольных метаданных;
используйте сохранённые отчёты доверенного сканирования.

Чтение ограничено обычными файлами: FIFO и другие специальные файлы отвергаются
без ожидания данных. Лимиты — 32 отчёта, 32 МиБ на файл, 128 МиБ фактически прочитанных
байтов и 100000 элементов JSON-массивов суммарно. Последний лимит применяется до
аллокации структур отчёта. Дубли полей, повреждённая Unicode, неверный envelope
и противоречивая полнота отвергаются. `source_error`, skipped и другие markers
не могут превратить неполный скан в подтверждённое отсутствие.

`correlate`: код 0 для полного результата, 2 при ошибке или неполноте.
`remediation-check`: код 1, если секрет остаётся `present`; код 0 при полном
сопоставимом результате без `present`; код 2 при ошибке, неполноте или
несопоставимости. Код 0 сам по себе не означает `closed: true`.

## Локальная квалификация

`python3 scripts/check_correlation_contract.py /path/to/prowl` использует настоящие
JSON-отчёты CLI, собственные identity keys и Git-объекты. Проверяются presence,
неполнота/фильтрация, разные ключи, shared blob metadata, input budgets и отказ
от противоречивых данных. Provider verdicts в части этой матрицы заданы фикстурами;
это проверка интерпретации полей, не подтверждение отзыва реального credential.
Evidence: `evidence/1.5.0-correlation-contract-20261114.json`.
