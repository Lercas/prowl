# Гейт качества детекта перед 1.5.0

`benchmark/` — локальный исследовательский каталог, исключённый из Git. CI не должен
зависеть от его наличия или создавать baseline при первом запуске. Runner продукта
находится в `scripts/quality/gate.py`, политика — в `scripts/quality/policy.json`.

CI и release qualification получают корпус из `Lercas/prowlbench` по полному commit
`53d6fc1e2006185c0fadd5cd761af3f1aacfd025`. Runner дополнительно проверяет SHA-256
файла, число записей, уникальность ID и состав выборки. Используется каждая восьмая
строка из 24603: прежние 3076 примеров, 2094 положительных и 982 трудных отрицательных.
Для всех выбранных записей ID, текст, метка и источник совпали с прежним локальным
`benchmark/ci_subset.jsonl`. Сам корпус в репозиторий сканера не копируется.

Сохраняется прежний протокол носителей: `code` → `.py`, `log` → `.log`,
`confluence` → `.md`, остальные → `.txt`. Изменение расширений ради улучшения цифр
изменило бы измеряемую задачу и не исправило бы детектор.

Сканируется статический CLI со встроенными rules/verifiers и L2, без пользовательского
конфига, установленных моделей, overlays, identity key и переменных `PROWL_*`.
Provider verification, OCR и semantic discovery не включаются. Файлы находятся
в новом временном каталоге. Проверяются успешный exit, `complete`, `truncated`,
число обработанных файлов, исходные байты и принадлежность путей находок выборке.
Неполный скан, изменённый корпус, пустой/повреждённый JSON или недоступный binary
дают код `2`, без квалифицированных метрик. Содержимое subprocess stdout/stderr
не печатается и не переносится в итоговый отчёт.

Счёт ведётся по файлам: хотя бы одна находка в положительном примере — попадание,
в отрицательном — ложное срабатывание. Несколько находок не увеличивают число
попаданий. Это recall и T4 false-positive rate на данном subset, а не span-level
accuracy, общая precision, доля живых ключей или качество на произвольных источниках.

Исторические пороги сохранены без снижения: recall `0.7469`, T4 FP `0.058`,
допуск `0.005`. Runner не обучает модель и не создаёт/меняет baseline. Минимальный
recall — `0.7419` (1554/2094), максимальный T4 FP — `0.063` (61/982).
Регрессия даёт код `1`; успешная квалификация — `0`. Выходной JSON создаётся
исключительно новым файлом и содержит только метрики, публичные ID случаев,
политику и hash binary. Положительный результат не разрешает публикацию сам по себе.

```sh
python3 -m unittest discover -s scripts/quality -p 'test_*.py'
python3 scripts/quality/gate.py --binary /path/to/static-prowl \
  --dataset /path/to/pinned-prowlbench/prowlbench.jsonl \
  --output /path/to/new-quality-report.json
```

Гейт подключён к обеим версиям Go в CI `static-ml` и к release `qualify` перед
созданием бинарных артефактов. Локальная проверка 2026-11-15 на исходниках
`268bc7c`: **регрессия**, 1517/2094 (72,45%) и 53/982 (5,40%). Порог ложных
срабатываний пройден, recall — нет; до нижней границы не хватает 37 попаданий.
Этот отказ оставлен видимым: baseline, модель и расширения носителей не изменены.
Исправление recall остаётся отдельной обязательной работой до релиза.

При сохранённых данных и порогах кандидат проходит: 1556/2094 и 57/982.
Исторический отказ выше сохранён как исходная точка, а не текущий статус.
