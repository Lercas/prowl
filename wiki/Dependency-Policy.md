# Зависимости и проверка уязвимостей

Для сборки требуется Go 1.26.11 или новее. Релизный workflow, Dockerfile и основная
CI-проверка закреплены на Go 1.27.4. `tool/go.mod` предлагает ту же версию через
`toolchain`; явный `GOTOOLCHAIN=go1.26.11` проверяет минимальную поддерживаемую версию.

Установите закреплённый checker и запустите из `tool/`:

```sh
go install golang.org/x/vuln/cmd/govulncheck@v1.9.0
make vuln
GOOS=windows GOARCH=arm64 CGO_ENABLED=0 make vuln
```

CI проверяет статическую конфигурацию для Linux, macOS и Windows на amd64/arm64,
а также Linux/amd64 на минимальном Go. Перед выпуском workflow повторяет проверку
шести релизных целей. Анализ использует текущую базу `https://vuln.go.dev` и блокирует
продолжение при ненулевом коде, включая ошибку самого checker. Исключений по ID нет.
Отсутствие известных уязвимостей относится к дате и конфигурации проверки.

Обновление `klauspost/compress` требует отдельной проверки L2: компрессор определяет
численный признак модели. При изменении признаков нужна новая версия схемы и новая
квалификация модели; старый JSON нельзя сделать совместимым переименованием поля.
В 1.5.0 переход v1.18.6 → v1.20.4 изменил 12735 из 525102 значений признака сжатия.
Прочие 48 признаков совпали. Модель `compression_ratio_go_flate_v2` переобучена;
отчёт, в том числе отклонённый кандидат, хранится в
`tool/internal/mlmodel/testdata/portable_qualification.json`.

Первый кандидат с 127 листьями не прошёл test-гейт. Повторный выбор использует меньшую
модель при разнице validation F1 до 0,0001; окончательный кандидат имеет 63 листа.
Это повторная квалификация на том же корпусе, а не новый независимый benchmark.
Данные test не входят в fit и не передаются функции выбора кандидата.

На отдельном локальном ProwlBench subset чистый кандидат нашёл 1580/2094 секретов
и дал 63/982 ложных срабатывания. Предыдущий чистый коммит дал 1565 и 64 соответственно.
Исторический порог FP 0,058 + 0,005 не проходит ни одна из этих сборок; он не повышался.
Поэтому переквалификация L2 и отсутствие известных уязвимостей не означают полного
релизного допуска. Этот subset и его baseline находятся в локальном исследовательском
стеке и пока не входят в Git/CI.

Обновление HTML-парсера также изменило дерево для потомков `select`, которые текущий
HTML Standard сохраняет. Тесты теперь проверяют эти ресурсы и отдельно подтверждают,
что вложенный чужой `base` не расширяет авторизованную область сканирования.
