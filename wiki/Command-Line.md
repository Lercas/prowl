# Аргументы команд в 1.5.0

Каждый флаг имеет область команд. Имя, алиасы, тип значения, проверка и строка
help задаются вместе в `tool/cmd/prowl/flags.go`. Например, `--recon` принадлежит
`domain`, а `--source` — только `rules update` и `verifiers update`.

```sh
prowl scan ./src --format=json
prowl domain example.com --authorized --recon
prowl mobile app.apk --min-run=5 --no-strings=false
prowl rules update --source=./operator-rules --check
prowl rules update --help
```

Сохранены короткие формы из 1.4.0: `prowl ./src` равнозначен `prowl scan ./src`.
Без аргументов сканируется текущий каталог, а при перенаправленном stdin читается
стандартный ввод. Имена явных команд имеют приоритет над одноимёнными файлами;
для такого файла используйте `./scan`, `./guard` и т. п.

`prowl --ci ./src` задаёт порог `high`: находки high/critical дают код 1,
полный скан без таких находок — 0, неполный скан — 2. Явный `--fail-on` имеет
приоритет независимо от порядка флагов. `--ci` не включает ML, OCR и сетевую
верификацию. `--ci=false` отменяет только порог этого флага: неполный скан
по-прежнему завершается кодом 2.

`--authorized` подтверждает разрешение владельца на перечисленные цели. Не
передавайте его для чужого ресурса без соответствующей авторизации.

При чужом флаге команда возвращает код 2 до чтения источника, подключения к
провайдеру или записи отчёта. Неизвестное имя получает подсказку среди флагов
этой команды. `scan ./src --recon` больше не пытается сканировать файл `--recon`.
Подкоманды проверяются отдельно: `rules list --source=...` также является ошибкой.

Флаги могут находиться до, после и между целями. Поддерживаются обе формы
`--format json` и `--format=json`, а также алиасы вроде `-o report.json`.
Разделитель `--` завершает разбор флагов:

```sh
prowl scan -- --literal-file-name
prowl scan ./src --exclude=--literal-substring
```

Если значение начинается с дефиса, используйте форму с `=`. Пропущенное или
пустое значение — ошибка. Следующий флаг, включая короткий `-q`, не может
случайно стать значением `--output`.

Повторяемые списки сохраняют все значения в исходном порядке, например
`jira --project=A,B --project=C`. У скалярных и boolean-опций действует последнее
значение. Для boolean разрешены `true/false`, `yes/no`, `on/off`, `1/0` и краткие
формы `t/f`, `y/n`. Неизвестное значение является ошибкой, а не молчаливым `false`.
`--authorized=false` не разрешает сетевой аудит, а `--current-only=false`
сохраняет сканирование истории.

Явные CLI-дефолты имеют приоритет над конфигом: `--format=pretty`,
`--max-size=10MB`, `--workers=0` не заменяются настройками файла.

`scan --stdin-name production.json` читает стандартный ввод и использует имя только
как метку и подсказку формата. Файл по этому имени не открывается и не создаётся.
Допустимы отсутствие позиционных аргументов или единственный `-`; пути и Git-режимы
несовместимы с этим флагом. В текущем кандидате восстановлен транспорт stdin;
обработка логических JSON/YAML/TOML-значений из 1.4.0 ещё требует восстановления
и остаётся блокером совместимости в `TODO.md`.

Неподдерживаемые режимы теперь отклоняются явно. Например, `serve` исполняет
каскад и правила, поэтому не принимает `--ml` и `--verify`. OCR доступен у
`scan`, `repo` и `org`. `compare` повторяет сканирование и не поддерживает OCR.
`--project` относится к Jira, `--space` — к
Confluence. Все фактически поддерживаемые Git-режимы `repo` сохранены.

Парсер возвращает ошибки вызывающему коду. Единственный `os.Exit` находится в
`main`, после возврата `runCLI`, поэтому ошибки не обходят deferred cleanup
обработчиков. Обработчики, конфигурация, сканирование и отчётность разнесены
по файлам; `main.go` содержит только входную точку и диспетчеризацию.

Сквозной индекс включается только явно: `--index DIR --scope NAME`. Команда
`prowl index --index DIR` показывает места обнаружения и историю проверок,
`prowl diff --index DIR --scope NAME` сравнивает последние два снимка, требуя
полноту обоих; более новый неполный результат не пропускается. Области флагов
не включают `compare`, worker, MCP и LSP. Подробности — [локальный индекс](Secret-Index.md).

Режим `scan/repo/org --git-timeline` включает историю и добавляет датированные события
появления/прекращения наблюдения, HEAD и окно экспозиции в JSON/SARIF. Семантика веток,
неполного покрытия и ограничений описана в [хронологии Git](Git-Timeline.md).

Команды `agents` (целевой аудит конфигов/текстовых транскриптов) и `guard` (stdin-хук
перед prompt/tool) описаны в [защите поверхности агентов](Agent-Security.md).
