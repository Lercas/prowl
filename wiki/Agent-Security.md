# Конфиги агентов и проверка перед передачей

## Целевой аудит

```sh
prowl agents . --format json -o agents.json
prowl agents --agent-home "$HOME" --format sarif -o agents.sarif
prowl agents . --agent-home "$HOME" --shell-history --ml
prowl agents exported-transcript.jsonl --index ./private-index --scope agent:exports
```

Без путей команда проверяет известные агентские пути текущего проекта. Явный
`--agent-home DIR` без путей проверяет только этот home; с путями — оба набора.
Домашний каталог и история оболочки не добавляются автоматически. Реальные личные
транскрипты не нужны для установки или тестирования функции.

В проекте выбираются `.mcp.json`, `mcp.json`, `.cursor`, `.claude`, `.codex`, `.agents`,
`AGENTS.md`, `CLAUDE.md`, `.cursorrules`. В явном home — `.claude`, `.cursor`, `.codex`,
известные конфиги Claude/Cursor под `.config`, macOS Application Support и Windows
AppData. `--shell-history` добавляет `.zsh_history`, `.bash_history`, историю fish и
требует явный `--agent-home`. Можно передать отдельный текстовый экспорт файлом.

В выбранных каталогах читаются JSON/JSONL/NDJSON, TOML, YAML, Markdown/MDC, текст,
логи, INI/CONF/CFG, ENV/XML и известные extensionless-конфиги. Источники получают
`agent.product` и `agent.kind` в JSON и SARIF properties; текстовые транскрипты и
история имеют `source: log`, конфиги и инструкции — `code`. SQLite/VSCDB, бинарные
истории редакторов и содержимое произвольных каталогов home этим режимом не читаются.

Ссылки, обнаруженные при обходе, не прослеживаются; чтение ограничено выбранным
корнем и проверкой идентичности файла при открытии. Нечитаемые/слишком большие
выбранные файлы, бинарные данные в текстовом конфиге и лимит 10000 файлов дают
диагностику неполноты. Действуют `--max-size`, `--exclude`, исключение собственного
каталога индекса и обычные ограничения детектора. Повторяющиеся пути не читаются дважды.

Аудит игнорирует автоматически найденные `.prowl.yaml`, `.gitleaks.toml`, baseline,
`.gitleaksignore` и каталоги шаблонов. Inline-прагма внутри транскрипта не подавляет
его находки. Оператор может явно выбрать `--config`, `--rules`, `--rules-dir`,
`--baseline`, ML и верификацию. Маскирование включено по умолчанию; домашний аудит
может содержать личные пути и требует обычного обращения с конфиденциальным отчётом.

## Хук

```sh
printf '%s' 'Текст перед отправкой' | prowl guard
prowl guard --protocol claude < event.json
prowl guard --protocol cursor-prompt < event.json
prowl guard --protocol cursor-tool < event.json
```

`guard` читает ровно один payload из stdin и использует встроенный L1-детектор.
ML, live-верификация, sidecar, OCR, конфиги проекта, baseline и внешние правила не
подключаются. У хука нет флагов раскрытия или сохранения значений; он не пишет
индекс, payload или находки на диск и не исполняет команды из входа. Пути, URL,
`cwd` и `transcript_path` из JSON не открываются. Inline-прагмы не дают исключений.

| Протокол | Принимает | Чистый payload | Находка или неполная проверка |
|---|---|---|---|
| `raw` | UTF-8 текст | JSON `decision: allow`, exit 0 | `block`, exit 1; ошибка — `error`, exit 2 |
| `claude` | `UserPromptSubmit`, `PreToolUse` | exit 0, stdout пуст | exit 2, постоянное сообщение в stderr |
| `cursor-prompt` | `beforeSubmitPrompt` | `continue: true`, exit 0 | `continue: false`, exit 2 |
| `cursor-tool` | `preToolUse`, `beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile` | `permission: allow`, exit 0 | `permission: deny`, exit 2 |

Адаптеры проверяют обязательные поля и декодируют строковые аргументы, включая
вложенные объекты; JSON сохраняет точные числовые значения. Дубликаты полей,
повреждённый Unicode/UTF-8, неизвестное событие, отсутствующие данные, исчерпание
лимитов и ошибка записи ответа блокируют передачу. В ответе нет исходного значения,
маскированного фрагмента или скопированного текста ошибки парсера.

По умолчанию payload ограничен 1 МиБ, жёсткий максимум — 8 МиБ; таймаут — 3 с,
разрешено до 30 с. Дополнительно ограничены развёрнутый текст (8 МиБ), 8192 части
и 32 уровня вложенности. Чистый результат означает отсутствие распознанных кандидатов,
а не доказательство отсутствия секрета при любой неизвестной обфускации.

## Подключение к клиентам

Шаблоны находятся в `integrations/agent-hooks/claude.settings.json` и
`integrations/agent-hooks/cursor.hooks.json`. Они не устанавливаются автоматически.
Замените `/absolute/path/to/prowl` на доверенный абсолютный путь к установленному
бинарнику и объедините соответствующий раздел с текущей конфигурацией клиента,
сохранив другие хуки. Шаблон с неизменённым placeholder не работает.

Для Claude Code предусмотрены синхронные `UserPromptSubmit` и `PreToolUse`, exec-форма
command/args, `onFailure: block` и внешний таймаут 10 с. Эта обработка ошибки запуска
требует Claude Code 2.1.295+; без неё отсутствие бинарника или таймаут может разрешить
действие. Контракт проверен по [официальной документации Claude Code](https://code.claude.com/docs/en/hooks).

Для Cursor предусмотрены `beforeSubmitPrompt`, `preToolUse` и `beforeReadFile`;
`failClosed: true` обязателен для ошибки запуска, падения и таймаута. При отдельной
интеграции legacy shell/MCP-хуков используйте тот же `cursor-tool`. Форматы и флаги
сверены с [официальной документацией Cursor](https://cursor.com/docs/hooks) на 2026-11-14.

## Границы

Хук проверяет предоставленные байты. Путь к файлу сам по себе не предоставляет его
содержимое: Claude `PreToolUse` не даёт универсального контроля над будущим результатом
`Read`, расширением навыков или неявными `@`-вставками. Cursor `beforeReadFile` проверяет
именно переданный `content`; дополнительного чтения по `file_path` нет. Prompt с
непустым списком attachments блокируется как непроверенный: их содержимое отсутствует
в payload этого события. Между вызовами нет кэша разрешений, на который можно было бы
ошибочно опереться после изменения файла.

Это локальный барьер для поддержанных payload, а не песочница инструментов, анализ
любого зашифрованного содержимого или контроль всего сетевого трафика. Подключённый
host должен реально исполнять синхронный хук, сохранять блокирующий exit/status и
использовать режим отказа с блокировкой. Локальные тесты stdin/stdout и шаблонов не
заменяют проверку установки в конкретном клиенте; такая установка отдельно не выполнялась.
