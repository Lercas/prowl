# Сквозной локальный индекс

Индекс связывает одинаковое значение между файлами, репозиториями, Jira/Confluence,
образами, мобильными приложениями и другими источниками. Он включается явно:

```sh
prowl scan ./src --ml --index "$HOME/.prowl/index" --scope repo:payments
prowl jira https://jira.example.com --index "$HOME/.prowl/index" --scope jira:team
prowl index --index "$HOME/.prowl/index"
prowl index --index "$HOME/.prowl/index" --format json -o index-report.json
```

`--index DIR` задаёт отдельный каталог состояния, `--scope NAME` — стабильную область
сбора. Для сканирования оба флага обязательны вместе. Одна область должна описывать
одни и те же источники и настройки отбора; различающиеся репозитории и экземпляры
сервисов получают разные имена областей. Команды `index` и `diff` читают существующий
индекс; они не создают новый каталог, ключ или базу при ошибке пути.

Индекс поддерживают `scan`, `repo`, `org`, `cicd`, `image`, `mobile`, `bucket`, `domain`,
`jira`, `confluence`, `agents`. Сетевые команды сохраняют свои обычные требования авторизации.
`compare`, HTTP worker, MCP и LSP не включают постоянное хранение через этот флаг.

## Что хранится

В каталоге создаются `key` — случайный 32-байтовый локальный ключ — и `index.sqlite`.
На Unix каталог требует прав 0700, файлы — приватных прав без group/other access.
Новый каталог на Windows получает защищённый DACL для текущего пользователя, SYSTEM
и Administrators; существующий DACL проверяется и не заменяется. Ссылки и hardlink-алиасы
файлов состояния отклоняются. Собственный каталог исключается из физического чтения
файлов, включая явные symlink- и регистровые алиасы на нечувствительной к регистру ФС.

Идентификатор значения — HMAC-SHA256 от точных байтов значения с разделением доменов
и версией формата. Он не включает тип, источник или путь. Ключевой namespace включён
в идентификатор: разные локальные ключи не создают общий публичный словарь отпечатков.
Обычный `fingerprint`, используемый baseline и SARIF alert identity, сохраняется.
Дополнительный `value_fingerprint` появляется в JSON и свойствах результата SARIF
только при явном включении индекса.

SQLite сохраняет идентификатор значения, область, тип, источник, безопасный путь,
строку/столбец и результат верификации. Исходное значение, `redacted`, контекст строки,
URL-поле отчёта и rationale не копируются в базу, даже с `--show-secrets`. Из пути
удаляются все обнаруженные в этом файле значения, URL credentials, query и fragment.
Та же очистка применяется к меткам источника и типа перед сохранением и передачей
подтверждений верификации. Идентификатор места отдельно
вычисляется по исходным координатам, затем привязывается к области: одинаковые имена
файлов разных репозиториев и URL с разными query-параметрами не сливаются.

Отчёт показывает число **исторически наблюдавшихся позиций** — область, источник,
путь, строка и столбец. Это не число активных размещений в текущем окружении. Повторные
сканы одной позиции не увеличивают счётчик; перемещение по строкам создаёт новую позицию.
Значения связываются между областями, но сравнение отсутствия выполняется внутри одной.

Наблюдения записываются после детектора, allowlist и ML, но до `--verified-only`,
baseline, `--disable`, severity/confidence-фильтров, CLI dedupe и ограничения отчёта
на файл. Все отдельные позиции шаблонов сохраняются в режиме индекса. Подтверждённые
ответы верификатора отдельно сохраняются до ML, чтобы отклонённый провайдером ключ
не исчез из истории из-за подавления его отображения моделью.

## Новое с прошлого скана

```sh
# Повторный сбор той же области
prowl scan ./src --ml --index "$HOME/.prowl/index" --scope repo:payments

# Последние два скана области; оба должны быть полными
prowl diff --index "$HOME/.prowl/index" --scope repo:payments

# Явно выбранные исторические снимки
prowl diff 12 18 --index "$HOME/.prowl/index" --format json
```

`new_values` содержит ранее не наблюдавшиеся в предыдущем снимке значения;
`new_locations` — новые позиции. `not_seen_values` и `not_seen_locations` означают
отсутствие в выбранном новом сборе, а не доказанный отзыв ключа. Изменение входов,
детекторов, allowlist или ML может изменить набор наблюдений.

Неполные сканы сохраняются с `complete: false`. Отмена, ограничения детектора,
ошибки источника, неполное OCR-покрытие и пустой сбор CI не становятся доказательством
отсутствия. `diff` отказывается сравнивать неполные снимки и разные области. Автоматический
выбор последних двух сканов не пропускает более новый неполный скан ради старой зелёной пары.

## Подтверждение отзыва и время устранения

Состояния опираются на уже существующий контракт `--verify`: `true` — provider-confirmed
live, `false` — провайдер отклонил credential, `null` — нет однозначной проверки.
Неизвестный ответ или исчезновение из скана не превращаются в `dead`. При смешанных
наблюдениях одного значения live имеет приоритет; dead/unknown остаётся unknown.
Неполные снимки не обновляют подтверждённое состояние.

Отчёт хранит дату последнего подтверждения и переходы `live → dead` / `dead → live`.
`seconds_since_first_live` — интервал между завершением первого live-скана текущего
периода и первым последующим подтверждённым dead-сканом. Это наблюдаемый интервал,
а не точное время утечки или отзыва. Переход подтверждает изменение ответов проверки
старого credential; работоспособность ключа-замены автоматически не утверждается.

Снимок и его наблюдения сохраняются одной SQLite-транзакцией. Отчёт файла/stdout
записывается отдельно: ошибка доставки отчёта не отменяет уже сохранённый полный сбор.
`--output` и `--write-baseline` не могут перезаписать файлы внутри каталога индекса.

Для восстановления нужны исходные `key` и `index.sqlite` вместе. Отсутствующий,
повреждённый или несовпадающий ключ не заменяется автоматически. Повторно вычислить
старые HMAC без исходных значений невозможно. Автоматического удаления истории,
ротации ключа индекса и разрушительных миграций в этой версии нет.

Backend `modernc.org/sqlite` сохраняет сборку с `CGO_ENABLED=0`. Локально проверяются
Unix-контракты и шесть релизных целей компиляции; отдельный Windows CI проверяет ACL
нативно после внешнего запуска workflow. Компиляция не заменяет этот запуск.
