# Аудит публичных ключей

В 1.5.0 добавлены отдельные проверки публичных ключей для `domain` и `mobile`:
ACL Algolia и [read-only Firebase](Firebase-Public-Audit.md). Ниже — контракт Algolia.

```sh
prowl mobile owned.apk --audit-public --authorized --format json
prowl domain owned.example --audit-public --authorized --format sarif
```

`--authorized` подтверждает право проверять и исходный объект, и найденные в нём
провайдерские ресурсы. Один этот флаг не включает аудит. Без подтверждения команда
отказывает при разборе аргументов, до чтения источника и обращения к провайдеру.
Флаг не доступен в MCP, LSP, HTTP server и остальных CLI-командах.

Аудит работает после ML, если ML включён. Он использует только победившие
кандидаты и их исходные значения. Нужны тип `algolia-api-key` и application ID из
того же безопасно разобранного объекта JSON, YAML или TOML. Имена свойства ID:
`algolia_app_id`, `algolia_application_id`, `application_id`, `app_id`; регистр и
разделители `_`, `-`, `.` несущественны. Значение — ровно 10 латинских заглавных
букв или цифр. Родительский или соседний объект не считается источником привязки.
Неоднозначные дубли, повреждённый документ и отсутствие привязки запрещают запрос.
Также поддерживаются статические пары в JS: свойства одного объекта или значения
одной `const`-декларации. JS-совместимый текст в `.ts` разбирается тем же способом.
Специфичный синтаксис TypeScript/JSX, XML/plist, строки dex, ссылки на другие
переменные, отдельные декларации и пары из разных файлов пока не связываются.

## Привязки JS

```js
const config = {appId: "ABCDEF1234", algolia_api_key: "<key>"};
const ALGOLIA_APP_ID = "ABCDEF1234", ALGOLIA_API_KEY = "<key>";
```

Привязка основана на AST закреплённого Sobek
`v0.0.0-20261105103427-a5b602015248`: в бинарник включены только parser/ast и
вспомогательные пакеты, без JS runtime. Сначала разбирается ES module, затем при
необходимости script. Импорты не загружаются, программы не выполняются,
автоматическое чтение source maps отключено в обоих режимах. Парсер не влияет
на обычное сканирование без `--audit-public`.

Кандидат должен принадлежать диапазону конкретного свойства/инициализатора и
совпадать с его полным статическим значением. Одинаковый ключ в другом объекте
не может предоставить app ID. Комментарии, regex и текст внутри строки не
становятся объектами конфигурации. Поддерживаются строковые литералы, пустые
шаблоны без interpolation/tag и конкатенация только статических строк.
Неизвестное значение alias-свойства сохраняется как неизвестное: другой alias
не может незаметно подменить его. Spread, computed names, getters, методы и
дубли запрещают привязку всего объекта. Изменения объекта во время исполнения
не моделируются: результат описывает наблюдённую пару в исходнике.

Разбор выполняется лениво после ML и один раз на исходный item, включая его
reconstructed child scans. Диапазоны child привязаны к исходному выражению.
Состояние не разделяется между item или вызовами общего Pipeline. Поиск по
диапазонам использует отсортированный индекс; сами карты привязок не сериализуются
в report или SQLite. Обычный `--show-secrets` по-прежнему может раскрыть значение находки. Лимиты: 1 МиБ исходника, 100 000 AST-узлов, глубина обхода
256 с учётом контейнеров, 512 групп, 4096 полей, 128 свойств на группу и 64 КиБ
на статическую строку. До AST-разбора ограничиваются числовые атомы размером
4096 байт, чтобы не преобразовывать огромные BigInt. Проверка консервативна и
может отказать для похожей последовательности внутри текста. Ошибка синтаксиса, отмена, общий лимит или исключение
парсера отбрасывают привязки; подходящий ключ получает `inconclusive`.

Проверка посылает один GET собственного ключа в фиксированный HTTPS endpoint
`{applicationID}.algolia.net/1/keys/{key}`. Это документированный способ прочитать
ACL как admin, так и обычным ключом для самого себя:
[Algolia: Retrieve API key permissions](https://www.algolia.com/doc/rest-api/search/get-api-key).
Произвольные endpoint, перебор ключей, индексов и записей, запись данных и переходы
по редиректам отсутствуют. Сетевая защита `safehttp` применяется и к этой проверке.
Ключ неизбежно передаётся провайдеру в заголовке и URL, как требует его API;
сырые URL, ошибки, описания и тело ответа не попадают в отчёт или журнал.

Лимиты одной команды: 32 попытки запросов, четыре одновременных запроса,
64 КиБ ответа, timeout не более 10 секунд на запрос. Кеш объединяет одинаковые
пары application ID + ключ по SHA-256, без хранения исходной пары в ключе кеша.
Ошибки не кешируются как достоверный результат; повторные попытки тоже расходуют
общий лимит. У каждого запуска свой кеш и бюджет.

## Значения результата

JSON хранит результат отдельно в `public_key_audit`, SARIF — в `properties`;
отдельные occurrences сохраняют собственный результат. Pretty выводит строку
`public key audit`. Поля `verified` и `verification` аудит не устанавливает.

| Статус | Что установлено |
|---|---|
| `excess_permissions` | ACL содержит известные права сверх `search` |
| `search_only` | В ответе ACL состоит только из `search`; другие ограничения не оценены |
| `inconclusive` | Привязку или ACL нельзя достоверно установить |

Неизвестные права, повторные ACL-поля, несовпадающий ключ в ответе, неоднозначный
JSON, слишком большой ответ, HTTP-отказ, ошибка сети и исчерпанный бюджет дают
`inconclusive`. Провайдерские сообщения и неизвестные права не отражаются в отчёте.
Такой результат добавляет диагностический код `public_key_audit_inconclusive`,
делает покрытие неполным, приводит к exit 2 и запрещает обновление baseline.

Credential baseline не подавляет `public_key_audit`, в том числе в occurrences,
и не записывает идентичность таких находок. Принятие одного ключа не означает
принятие будущих изменений ACL. Явные фильтры отчёта и `.gitleaksignore`
сохраняют собственную семантику.
Неподдерживаемые типы не получают фиктивный результат аудита.

`search_only` не удостоверяет безопасность данных, referrer/IP-ограничений,
индексов, срока жизни или rate limit. Отсутствие разрешённого чтения ACL не
доказывает, что ключ мёртв или безопасен. `excess_permissions` не отличает
встроенный admin-ключ от пользовательского ключа с широкими правами.
Список известных ACL основан на
[официальной схеме Algolia](https://www.algolia.com/doc/rest-api/search/add-api-key).

Обычные severity и `--fail-on` сохраняются: поиск ключа и наблюдение его прав —
разные факты. `--audit-public` нельзя совмещать с `--verify`, `--verify-all`,
`--verified-only` и `--fail-on-verified`: существующие verifier-профили могут
включать другие операции. Базовые результаты и policy scope без нового opt-in
не меняются; включённый аудит получает собственную revision в coverage.

## Границы готовности

Проверены локальные транспортные, parser, cache/concurrency, pipeline и CLI
контракты. Финальные сетевые проверки используют локальный provider fixture;
реальный аккаунт не квалифицирован и требует отдельного разрешённого ресурса.
Полный пункт TODO остаётся открыт: прочие форматы/связи, надёжное распознавание admin,
Supabase и Google API restrictions ещё не реализованы; Firebase имеет отдельный
[ограниченный read-only контракт](Firebase-Public-Audit.md).

Локальная CLI-матрица — 32/32; полный Go-набор, race затронутых компонентов,
lint и минимальный Go 1.26.11 проходят. Зафиксированы отдельные source/binary
revision и границы Docker-кандидата:
[evidence](evidence/1.5.0-public-key-audit-20261115.json).

JS-привязки отдельно сверены с 72 эталонами Node.js 22.23.4. Node нужен только
для воспроизводимого генератора доверенных тестовых литералов, не для работы
Prowl. Успешная цепочка L1 → ML survivor → AST binding → реальный HTTP GET →
раздельный ACL-результат проверена на локальном provider fixture; подмена
транспорта существует исключительно в `_test.go` и отсутствует в CLI-бинарнике.

Нативная JS-матрица — 37/37 под macOS sandbox с запретом `network*`. Граница
сети предварительно проверена на доступном локальном endpoint: обычный запрос
дошёл, sandboxed-запрос не дошёл. Восемь L1-сценариев получили привязку, но
провайдерский транспорт был запрещён ОС. При включении неизменённой ML-модели
два кандидата сохранились, шесть были отфильтрованы. Это проверка порядка стадий,
не оценка качества модели. Ещё 14 неоднозначных JS-сценариев отказали до транспорта.

Для этой квалификации явно выбран portable JSON с 51 признаком. Существующий
`~/.prowl/model_binary.json` с 49 признаками корректно вызывает отказ при `--ml`;
его автоматически не заменяли и не переименовывали. Бинарник с текущим исходным
кодом и работающая локальная установка — отдельные границы готовности.
[JS evidence](evidence/1.5.0-public-js-bindings-20261115.json) содержит проверки,
source/binary/model hashes, границы локального HTTP fixture и cross-compile.
