# Поиск кандидатов моделью

`--semantic` включает отдельный opt-in этап поиска кандидатов через уже запущенный
OpenAI-compatible endpoint. Он дополняет L1, а `--ml` по-прежнему означает фильтр
готовых кандидатов переносимой Go-моделью. Это разные этапы.

```sh
prowl scan incident.txt --semantic --format json
prowl scan config.json --semantic-url http://127.0.0.1:8080/v1/chat/completions --semantic-model local
```

По умолчанию используются `http://127.0.0.1:8080/v1/chat/completions` и имя модели
`local`. Можно передать `PROWL_SEMANTIC_URL`, `PROWL_SEMANTIC_MODEL` и
`PROWL_SEMANTIC_API_KEY`. API key передаётся заголовком и не включается в policy.
Переменные сами по себе этап не включают; явные `--semantic-url` и
`--semantic-model` включают его. `--semantic=false` оставляет этап выключенным,
если другие semantic-параметры не выбраны.

Endpoint по умолчанию ограничен loopback; DNS-ответы и порт проверяются при
подключении, proxy для локального endpoint отключён, redirects запрещены.
Удалённый endpoint требует `--semantic-allow-remote` и HTTPS. Исходный текст может
содержать секреты; этот флаг явно разрешает отправить его выбранному сервису.
Общая политика SSRF провайдеров при этом не меняется.

## Доказательство и полнота

Модель возвращает кандидатов с UTF-8 byte offsets. Go принимает только точное
совпадение значения с текстом: длина 6–512 байт и корректная UTF-8. Если модель
посчитала символы вместо байтов, диапазон восстанавливается лишь для единственного
точного вхождения. Выдуманное или неоднозначное значение отвергается.

Находка имеет тип `generic_semantic_secret`, этап `semantic-candidate` и evidence
`literal-semantic-span`. Она является кандидатом, а не подтверждением действующего
секрета. Типизированная L1-находка того же значения сохраняет приоритет. Allowlist,
настоящие pragmas, общий candidate budget, маскирование и HMAC identity применяются
общим Pipeline. JSON/TOML/YAML анализируются в нормализованном представлении;
диапазоны и evidence проецируются обратно на исходные escapes или scalar spans.
С `--reconstruct` модель не вызывается повторно для каждого производного JS-выражения.

Один документ ограничен 16 блоками по 8192 байта с перекрытием 512 байт и
128 кандидатами. Одновременно endpoint получает не более двух запросов от одного
engine, таймаут запроса — 45 секунд; общий CLI/MCP timeout также действует.
Ответ ограничен 64 КиБ, должен завершаться `finish_reason: stop`, содержать явный
массив `candidates` и не иметь дублирующихся JSON-полей или повреждённой Unicode.
Ошибка сервиса/ответа и достижение лимита отражаются как неполный скан: код 2,
`complete: false`, запрет записи baseline. Текст ошибки сервиса не попадает в отчёт.

## Область поддержки

Флаги доступны для `scan`, `repo`, `org`, `cicd`, `image`, `mobile`, `bucket`,
`domain`, `jira`, `confluence`, `agents`. В MCP используется `semantic: true`
в `tools/call`; endpoint задаётся окружением процесса. Startup-флаги сканирования
MCP не принимает. LSP не вызывает модель при вводе текста. HTTP worker `serve`
не принимает semantic-флаги CLI.

`compare --semantic` выполняет один intake и один проход L1/semantic/reconstruction.
Перед локальным L2 сохраняется ограниченная display-проекция кандидатов; после L2
сохраняются выбранные строки того же прохода. Повторного чтения источника и второго
независимого inference нет. Это набор наблюдений во время одного обхода, а не
атомарный снимок всего файлового дерева.

Суммарно raw/kept projections ограничены 100000 строками и 32 MiB оценённого размера
с консервативным overhead. Контексты, тела источников и scoring records в пуле не
удерживаются. Превышение лимита отменяет общий context источника/worker pool и даёт
код `2` без процента подавления. Так же обрабатываются неполный источник, ошибки или
неполные/NaN scores, ошибка semantic и отмена. Ошибки scorer не превращаются в
успешный «0% suppressed».

Compare использует только in-process L2, включая совместимую `--ml-model`.
Sidecar `--ml-url`, provider verification и verifier selection для compare
отклоняются. OCR и stdin сохраняют прежнее ограничение команды. Remote semantic
по-прежнему требует явный opt-in и HTTPS. Вывод compare остаётся текстовой сводкой;
он не измеряет ground-truth accuracy и не подтверждает действительность секрета.
По умолчанию строки группируются по fingerprint: сохранившийся context сохраняет
идентичность в группе. `--no-dedupe` считает отдельные принятые кандидатные строки;
одинаковое значение у оставшегося кандидата не скрывает подавление другой строки.

Воспроизведение: `python3 scripts/check_compare_contract.py /path/to/prowl`.
Используются синтетические файлы, собственный loopback inference stub и встроенный
L2. Проверяются также изменения файла во время inference и глобальный лимит пула.
Доказательства: [compare contract](evidence/1.5.0-compare-contract-20261114.json).

## Проверка реализации

`python3 scripts/check_semantic_contract.py /path/to/prowl` запускает реальный CLI
и четыре MCP-транспорта с собственным loopback stub. Проверяются JSON/SARIF,
файл/stdin, UTF-8/escapes и evidence, маскирование, opt-out, ошибки/выдуманные
значения и baseline guard. Evidence: `evidence/1.5.0-semantic-contract-20261114.json`.

Эта матрица не измеряет precision/recall реальной модели, качество её prompt,
доступность внешнего сервиса или пользу для заказчика. Реальная модель и совместная
retention с L2 требуют отдельной оценки; выводов о качестве по stub-тесту нет.
