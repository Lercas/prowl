# Калибровка ML для структурированных литералов

Локальный кандидат 1.5.0 устраняет 30 пропусков в нативной матрице JSON/YAML/TOML:
204/204 проверки проходят с файловым вводом и именованным stdin, с ML и без него.
Отчёт: `evidence/1.5.0-literal-calibration-20261114.json`.

Первые 49 признаков и порог 0,3 сохранены. Добавлены
`ctx_parser_literal_sensitive_v1` и `ctx_ui_namespace_v1`. Только полный пароль,
связанный парсером с реальным полем, получает область калибровки: Unicode,
пробельные/управляющие символы, экранирование, шаблонные/разметочные символы
или имя поля вне лексического словаря исходной модели. Типизированные секреты,
обычные ASCII-пароли и текст вне структурированных полей используют прежний лес.
Признаки не устанавливаются по поиску похожего текста внутри значения.

Калибровка обучена на фактическом контексте Pipeline; разбиение группирует
связанные значения и носители. Размер дерева выбирается только по validation.
Положительные и отрицательные примеры присутствуют в namespaces настроек и UI.
31-листный вариант выбран из 31/63/127. Идеальный результат синтетического holdout
не является оценкой качества на реальных пользовательских данных.

Вне области калибровки все 525102 оценки исходного корпуса совпадают побитово.
768 оценок совпадают между Python и Go; 31200 векторов совпадают между Go 1.26.11
и 1.27.4. На ProwlBench сохранены те же идентификаторы находок (1616/2094
положительных, 61/982 отрицательных). Дополнительная структурированная выборка
сохраняет 377 TP / 9 FP на 813 полных случаях; ещё четыре случая неполны в обеих
версиях и не объявлены успешными.

Ранее отклонены глобальное переобучение (ухудшение original-test) и калибровка
всех канонических паролей (новое ложное срабатывание и потеря обычного пароля).
Полная дополнительная выборка сохранена; область текущей калибровки ограничена
семантикой литерала и доказанным именем поля.

Новый встроенный файл — `model_binary_go_literal_v1.json`, SHA-256
`dc232e3c7b140845b935078cc63ac671bdfd72a21db7b56d41a4160cd2a010c3`.
Исходный 49-признаковый Go forest сохранён как reference. Внешняя старая модель
отклоняется до сканирования с указанием переобучения; автоматической перезаписи
пользовательской модели нет. Python sidecar использует отдельную лексическую
модель; равенство его каскада новой Go-модели не заявляется.

Проверены полный Go suite, race для затронутого runtime, минимальный Go,
Python unit-тесты и CGO=0-сборки darwin/linux/windows на amd64/arm64.
Установленная модель, опубликованные артефакты и production не обновлялись.
Остальные пункты совместимости с 1.4.0 и релизная квалификация остаются открыты.
