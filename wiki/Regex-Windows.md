# Regex-окна для минифицированного текста

`internal/linewin` используется встроенной таксономией и внешними правилами.
Анализатор доказывает обязательные литералы и хотя бы один способ ограничения
региона: длину по байтам, количество разделителей или число межстрочных переходов.
Если доказательства нет, regex продолжает работать по всему тексту.

Если длинного обязательного литерала нет, AST может доказать структурный якорь:
разделитель непосредственно после обязательного ASCII-класса длиной от восьми
символов. Например, `[0-9]{8,10}:` индексируется по `:`, но окно строится только
после проверки восьми предшествующих цифр в исходном тексте. Для альтернатив
доказательство обязательно в каждой ветви; необязательные группы и Unicode-классы
такого доказательства не дают. Проверяемый суффикс ограничен 64 байтами; для более
длинного класса это остаётся необходимым условием совпадения.
Это покрывает Telegram, Discord, UUID, MongoDB и Mailgun без специальных проверок
названий провайдеров. Обычная пунктуация не запускает отдельные regex-окна.

Для применимых regex есть три способа ограничить окно по байтам:

- Конечная максимальная длина совпадения выводится из AST regex. Учитываются все
  альтернативы, повторы, Unicode-классы и case-folding. Вокруг найденного литерала
  остаётся достаточно места для любого полного совпадения и соседнего UTF-8-контекста.
- При неограниченной длине AST даёт консервативное множество всех поглощаемых ASCII-символов.
  Разделитель вне этого множества не может находиться внутри совпадения. Если такие
  разделители или границы файла найдены с обеих сторон в пределах бюджета, они
  ограничивают окно. Например, `hf_[A-Za-z0-9]{34,}` можно ограничить соседними `;`.
- Если весь regex может поглотить любой ASCII-символ, отдельно анализируются неограниченные
  повторы. Остальные части имеют конечную длину B. Следовательно, совпадение может поглотить
  не более B ASCII-символов вне алфавита повторов. Окно ищет B+1 таких символов с каждой
  стороны литерала. Это позволяет ограничить `deepseek[\s_-]*key=…` без искусственного
  ограничения допустимых пробелов, дефисов или переносов строки.

Бюджет одного исходного окна — 8 КиБ. Пересекающиеся окна объединяются; их объединение
может быть больше 8 КиБ. Если регионы покрывают больше половины текста, дешевле выполнить
полный проход. Если разделители не найдены в бюджете, остаётся прежнее окно по строкам
или полный текст, если конечного межстрочного ограничения также нет. Бюджет повторного
поиска разделителей — две длины входа на regex; последняя проба может добавить до 8 КиБ.
После исчерпания бюджета выполняется полный проход. Это исключает просмотр 8 КиБ на каждый
литерал в плотном входе.
Поэтому длинный `KEY.*END` не обрезается ради ускорения: для него одно строковое окно
может по-прежнему совпадать со всем минифицированным файлом.

Конечная длина особенно важна при отсутствии результата: частичный regex на краю среза
может не дать никакого совпадения. Одной проверки «найденное совпадение касается края»
недостаточно, чтобы доказать отсутствие пропущенных секретов. Здесь границы сначала
доказываются, а проверка края служит дополнительной защитой.

Совпадение на искусственной границе повторно проверяется по всему тексту. Это сохраняет
семантику `^`, `$`, `\A`, `\z`, `\b` и жадных повторов. Байтовая граница не разрезает
валидный UTF-8; некорректные байты сохраняют поведение Go regexp. Лимит `FindAll`, группы
захвата и глобальные смещения остаются прежними.

Проверки включают прямое сравнение с Go regexp на случайных и длинных текстах,
неограниченные и слишком длинные совпадения, Unicode, повреждённый UTF-8, смешение
ограниченных окон с полным проходом и специальные случаи на границах.
Микробенчмарк `BenchmarkMinifiedRuleSearch` включает подготовку окон и поиск 32 regex
в синтетическом однострочном файле около 512 КиБ. Его результат не является общей
скоростью сканера: обязательный поиск литералов всё равно читает весь текст один раз.

Структурные якоря квалифицированы локально на 12044 файлах GOROOT: встроенный
детектор и 421 regex шаблонов дают ноль расхождений с полным проходом.
CLI с ML сохраняет все 2246 находок отложенного ProwlBench subset. Полный конвейер
на GOROOT в трёх чередующихся парах относительно фиксированной базы `e0f05cd`
даёт медиану 10,365 → 9,681 с; B/op +1,04%, allocs/op +0,047%.
Это результат данного корпуса и окружения, а не универсальная скорость сканера.
Отчёт: [структурные якоря](evidence/1.5.0-structural-regex-anchors-20261114.json).
Частый якорь `//` у `basic_auth_header` и общий допуск релиза остаются открытыми.
