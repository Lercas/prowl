# 🐱 Prowl - fast, configurable secret scanner (Go)

> *purr* + *purloin* (to filch) - finds purloined/leaked secrets.

Сканер секретов на Go: один статический бинарь, конкурентный, high-precision (checksum-валидация +
отсев example/placeholder + base64-размаскировка), с **внешней разведкой по домену**, **LSP-подсветкой
в редакторе** и лёгкой интеграцией в CI/CD. Использует таксономию и ML-каскад проекта `secrets_ml`.
Архитектура: [`docs/design/tool_architecture.md`](../docs/design/tool_architecture.md).

## Сборка
```bash
cd tool && go build -o prowl ./cmd/prowl     # таксономия встроена (embed)
# или: docker build -t prowl .
```

## Команды

Первый скан: `prowl` проверяет текущую папку, `prowl ./src` — выбранный путь,
`cat build.log | prowl` — stdin. Правила встроены; `rules update` не обязателен.
`prowl --help` показывает короткий старт, `prowl help all` — все возможности.

```bash
# Файлы / директории
prowl --ci ./src                               # --strict + --fail-on high; явный --fail-on имеет приоритет
cat config.yaml | prowl --stdin-name config.yaml  # YAML-парсер; имя не создаёт файл
prowl scan .                                   # текущая директория
prowl scan --format sarif --output out.sarif --fail-on high src/
prowl scan --format defectdojo -o dd.json .    # DefectDojo Generic Findings Import
prowl scan --ml .                              # + ML-фильтр ложных срабатываний (L2)
prowl scan --bundled --strict .                 # rules/verifiers встроены в релиз; installed-наборы сохраняются
prowl doctor --bundled                         # проверить выбранные наборы без provider requests

# Мобильные приложения (Android APK / iOS IPA)
prowl mobile app.apk                           # распаковка ZIP + скан ресурсов + strings из бинарей
prowl mobile app.ipa --ml --verify             # google-services.json/GoogleService-Info.plist и т.п.
prowl mobile https://cdn.acme.com/app.apk      # URL качается SSRF-защищённым клиентом во временную папку

# MCP-сервер (AI-агенты драйвят сканы как инструменты)
prowl mcp                                       # Model Context Protocol по stdio (JSON-RPC построчно)
# регистрация: claude mcp add prowl -- prowl mcp

# Git (для pre-commit и CI на PR)
prowl scan --staged                            # только staged-файлы (быстро)
prowl scan --since origin/main                 # diff с веткой (CI на PR)
prowl scan --history                           # все блобы git-истории

# Домен (нужен --authorized)
prowl domain acme.com --authorized             # HTML + __NEXT_DATA__/state + referenced JS + maps
prowl domain acme.com --authorized --recon     # + поддомены (crt.sh) + wayback
prowl domain --targets hosts.txt --authorized  # список хостов (по строке) через worker-pool
prowl org github:acme --gists                          # публичные gists github-юзера вместо репозиториев
prowl scan --show-secrets .                     # печатать ПОЛНОЕ незамаскированное значение + строку-контекст (триаж)

# Jira / Confluence (многоверсионно - каждая версия issue/страницы с самой первой)
prowl jira https://acme.atlassian.net          # Cloud (env: ATLASSIAN_EMAIL + ATLASSIAN_API_TOKEN)
prowl jira https://jira.acme.com --project OPS  # Server/DC (env: ATLASSIAN_PAT), один проект
prowl confluence https://wiki.acme.com --current-only  # только текущая версия (быстро, без истории)

# Редактор (LSP - подсветка секретов на лету)
prowl lsp                                       # запускается как Language Server (stdio)

# Baseline (заглушить принятые находки)
prowl scan --write-baseline .prowl-baseline.json
prowl scan                                      # авто-подхват baseline -> подавляет известные

prowl detectors                                 # список типов
```

Для `domain --targets`, `hermes-audit --targets` и отдельного `prowl-hermes-audit
--targets` используется одинаковое чтение списка: обычный UTF-8-файл до 16 МиБ,
не более 10 000 непустых строк без комментариев, до 4 КиБ на строку. Повторы удаляются
с сохранением порядка, но учитываются в лимите записей. Пустые строки и комментарии
`#` пропускаются; LF и CRLF поддерживаются. Ошибка чтения или превышение лимита даёт
код `2` до запросов к целям и без замены отчёта. FIFO отклоняются без ожидания;
исправные ссылки на обычные файлы поддерживаются.

`domain` сохраняет диагностику недоступных целей, даже когда другие хосты ответили.
Ошибки HTTP-чтения/закрытия, слишком большой ответ, отсутствующий явно указанный
ресурс, неверный recon-каталог и исчерпание лимита дают `source_error`, неполный JSON
и код `2`; доступные находки сохраняются. Отсутствие предполагаемого source map
(`404`/`410`) допустимо. Если ранее этот адрес уже вернул `200/204`, но чтение или
закрытие тела завершилось с ошибкой, последующий `404/410` не превращает сбор в чистое
отсутствие: сохраняются прочитанный фрагмент и диагностика неполноты. Доступный префикс
ответа сканируется в пределах 4 МиБ; из неполного HTML не извлекаются новые адреса.
Успешный повтор заменяет префикс полностью прочитанным телом, в том числе пустым.
Пустая успешная страница считается прочитанной, а inline state не расходует отдельный
бюджет запросов. У механизма повторов экспоненциальная задержка насыщается до лимита
без переполнения; неположительная начальная задержка или лимит отключают ожидание,
сохраняя ограниченное число попыток.
Счётчик последовательных отказов действует только внутри одного сканирования и
различает схему, хост и порт. После трёх неудачных чтений запросы к этому сервису
приостанавливаются на 30 секунд; успешное чтение сбрасывает счётчик. Другие порты
и последующие сканирования начинают с независимого состояния.
Одинаковый HTML на разных корнях не мешает загрузить относительные ресурсы каждого
хоста. Ссылки извлекаются из HTML-атрибутов, включая значения без кавычек и HTML entities;
учитывается первый HTML `<base href>` в дереве документа вне HTML `template`.
SVG/MathML-элементы `base` не меняют базовый адрес. Комментарии, CDATA, `data-src`,
строки внутри скриптов и теги, отброшенные HTML-парсером, не создают ссылки.
HTML внутри точек интеграции SVG/MathML разбирается как HTML.
Внешний `<base>` не расширяет разрешённое семейство хостов. Отказ парсера, включая
глубину вложенности свыше 512 элементов, даёт `source_error`, неполный отчёт и код `2`;
прочитанный текст и доступный inline state сохраняются, другие корни продолжают обход.
State-блоки выбираются по настоящим атрибутам `script` и `meta` в HTML-дереве:
порядок атрибутов, одинарные кавычки, значения без кавычек и пробелы вокруг `=`
не мешают извлечению. При дубликатах действует первое значение; `data-id`, `data-type`
и `data-content` не подменяют соответствующие атрибуты. JSON islands распознаются
по MIME type `application/json`, в том числе с параметрами. У `meta` проверяются
оба настоящих поля `content` и `value`; их HTML entities раскрываются один раз.
При отказе HTML-парсера доступный state извлекается из токенов, а отчёт остаётся неполным.
Inline state декодируется после HTML entities одним проходом по распространённым
JSON/JavaScript escapes, включая `\xNN`, `\uNNNN`, `\u{…}`, суррогатные пары
и переносы строк JavaScript. Буквальные обратные слеши не декодируются повторно;
некорректные escapes и одиночные суррогаты сохраняются как исходный текст.
Предполагаемый source map сохраняет параметры запроса JS-файла, выбирающие его версию;
также проверяется адрес карты без параметров, если сервер публикует её отдельно.
Fragment не участвует в адресе HTTP-ресурса.
После разрешённого редиректа относительные ссылки и `<base href>` разрешаются
от итогового адреса HTML-ответа. Этот адрес используется и в находках; при повторных
чтениях он остаётся связан с последним принятым телом или доступным префиксом.
Переход в другой origin или некорректный адрес ответа даёт неполный результат;
прочитанный текст сохраняется под исходным адресом без извлечения новых ссылок.
Если завершённое чтение JS-файла прошло через редирект, предполагаемые карты
проверяются также рядом с итоговым адресом. Повторяющиеся адреса этих карт в одной
группе загрузок запрашиваются один раз и расходуют общий бюджет ресурсов.
Параллельные загрузки выдают результаты в порядке исходного списка ресурсов:
при одинаковых телах выбирается первый адрес в этом списке, независимо от скорости
ответов. Это сохраняет путь и отпечаток находки при неизменном списке. Одновременно
ожидают выдачи не более 8 результатов для ресурсов страницы/recon-путей и 6 для
архивных ресурсов; бюджет также применяется в порядке списка.
Медленный ранний ответ задерживает выдачу следующих результатов; HTTP timeout
и отмена по-прежнему ограничивают ожидание.

Цель `domain` сохраняет явный порт и IPv6; URL выбирает точные схему и authority
корня хоста. Credentials и неверные адреса отклоняются до обхода всего списка;
пути/query/fragment не передаются в лог цели. Общие фильтры, дедупликация, лимит
находок на файл, baseline и `.gitleaksignore` применяются так же, как при `scan`.
Прерванный обход помечается неполным и блокирует запись baseline.

Отдельный `prowl-hermes-audit` также записывает JSON атомарно, с правами `0600` на Unix.
Он отклоняет ссылки и специальные файлы в месте вывода, сохраняет другие hardlink
на прежний файл и возвращает `2` при ошибке stdout, включая закрытый pipe на Unix.

Baseline и `.gitleaksignore` загружаются целиком до подавления находок. Отсутствие
автоматических файлов допустимо; отсутствующий явно заданный `--baseline`, ошибка
чтения, повреждённая ссылка, неверный формат или превышение лимита дают код `2`
без замены отчёта. FIFO и другие специальные файлы отклоняются без ожидания данных.
Оба файла ограничены 16 МиБ и 100 000 записей; строка `.gitleaksignore` — 1 МиБ.
Baseline содержит JSON-массив непустых строк fingerprint; старое пустое значение
`null` также допустимо. Ignore-файл содержит `путь:правило:строка` с необязательным
префиксом commit; комментарии `#` и пустые строки пропускаются. Частично прочитанные
списки не применяются. Обычные файлы через исправные ссылки поддерживаются.

Контекст отмены передаётся в общий этап отчёта и записи baseline для `scan`, `repo`,
`image`, `bucket`, `mobile`, `cicd`, `org`, `domain`, Jira и Confluence. Отмена после
детектирования или до атомарного commit блокирует baseline, сохраняя предыдущий
файл и очищая временный. В частичный отчёт добавляется диагностика неполноты;
код `2` имеет приоритет над кодом `1`. Завершённый commit не откатывается при более
поздней отмене.

Файлы отчётов заменяются атомарно в открытом родительском каталоге. При ошибке старый файл
сохраняется, команда возвращает `2`; временный файл очищается. Ссылки и специальные файлы
в месте назначения запрещены, другие жёсткие ссылки на старый файл не изменяются. Обычные
отчёты и Hermes JSON на Unix записываются с правами `0600`, в том числе при `--show-secrets`.
Baseline и экспорт встроенного taxonomy используют ту же атомарную запись с правами `0644` на Unix.
Корректные ссылки на родительский каталог поддерживаются. Ошибки stdout также дают отказ;
на Unix закрытый канал отчёта не обходит очистку скачанных данных. Неизвестный формат отчёта
отклоняется, а не превращается в pretty-вывод.

`--staged` читает содержимое индекса Git: частичное добавление в коммит, последующие правки
и перемещения файлов в рабочем дереве не меняют результат проверки staged-версии. Ссылки
в индексе сканируются как текст ссылки; содержимое внешнего файла по ссылке не читается.
`--since` проверяет текущие версии изменённых файлов. Оба режима работают из подкаталога
репозитория и возвращают пути относительно его корня. `compare` использует те же Git-источники.

Выбранный каталог detection rules с `MANIFEST.sha256` проверяется до компиляции: изменённый,
неуказанный или отсутствующий YAML блокирует сканирование с кодом `2`. Checksum и компиляция
используют одинаковые прочитанные байты. Лимиты: 512 КиБ на YAML, 8 МиБ на manifest,
64 МиБ YAML и 10 000 YAML-файлов на каталог. Повторяющиеся записи manifest запрещены;
пробелы в именах сохраняются. Авторский каталог без manifest и явно выбранный отдельный
файл поддерживаются. Проверка действует также в MCP, HTTP-сервере и LSP.

`version` и `rules update`/`verifiers update` возвращают `2` при ошибке установленного
`.prowl-rules.json`; обновление проверяет его до получения источника. JSON ограничен 8 МиБ,
требует согласованных `count`/`files`, уникальных известных полей и корректных путей/checksum.
`VERSION` источника ограничен 64 КиБ и одной UTF-8-строкой. FIFO, ошибки доступа и ссылки
за пределы выбранного каталога отклоняются. Provenance JSON заменяется атомарно внутри
открытого каталога, без изменения других жёстких ссылок на прежний файл.

`update` проверяет отдельную копию сохранённого снимка источника и устанавливает те же байты.
Ссылки в источнике и выбранных назначениях запрещены; запись шаблонов атомарна для каждого
файла и остаётся в открытом корне назначения при замене его пути. Лимит снимка — 64 МиБ,
10 000 YAML; `SCHEMA.md` — до 8 МиБ. Проверочная копия `--check` существует до
`UpdateResult.Close()` в Go API и автоматически освобождается в CLI. Ошибка не означает
откат всего набора.

Сбой выбранного подкаталога источника не переключает обновление на его родительскую
библиотеку. Git-диагностика ограничена 64 КиБ, ожидание дочерних каналов — одной секундой;
на Unix отмена останавливает группу процессов. Bundled-копия заменяет только недоступный
репозиторий по умолчанию: ошибки проверки, revision и установки дают код `2`, отмена также
не запускает резервную установку.

`update --check` считает изменения по фактическим файлам назначения, включая `SCHEMA.md`;
версия и метаданные учитываются отдельно. Установка создаёт checksum из проверенного снимка,
а последующая проверка CLI сверяет ожидаемые provenance/checksum и загружает библиотеку без
повторного подписания файлов. Ссылки, FIFO и другие специальные управляемые файлы назначения
дают отказ до записи; лишние обычные YAML отражаются в плане удаления.

Ошибка чтения staged-файла или Git-истории, неразрешённый конфликт индекса либо превышение
`--max-size` для выбранного blob-объекта дают диагностическую находку `source_error`,
`truncated: true` в JSON/SARIF и код завершения `2`. Диагностику неполного сканирования
не скрывают фильтры отчёта, baseline и `.gitleaksignore`; создать baseline из такого
результата нельзя. Пустой список staged-файлов возвращает обычный пустой отчёт с кодом `0`.

`--max-size` ограничивает фактически прочитанные байты файлов и stdin. Ошибки чтения,
повреждённые архивы/документы, превышение лимитов распаковки и сбои OCR также помечают
отчёт как неполный; уже полученные находки сохраняются. Явно исключённые элементы
архивов и почтовых вложений не расходуют лимит распакованного содержимого. Отмена
сканирования или сбой обработки дают `response_truncated` и код `2`. MCP возвращает
неполный JSON-отчёт с `isError: true`; обычные находки с кодом CLI `1` остаются успешным
результатом вызова инструмента.

При сканировании нескольких путей отсутствие одного файла сохраняет находки из остальных
путей в неполном отчёте. Для `cicd` ошибки скачивания и распаковки выбранных логов/артефактов
передаются в отчёт до применения фильтров и создания baseline, даже если другие логи
уже содержат секреты.

Ошибки загрузки правил выявляются до чтения или скачивания источника: недоступный шаблон,
неизвестное YAML-поле, неверный regex или AND/OR, а также ошибка внешнего `--rules` или
custom regex в конфигурации дают код `2` без создания отчёта и baseline. Частичный набор
не используется для сканирования. Команды `rules list/show/test/search/stats` и LSP также
отклоняют неполную библиотеку; `rules validate` сообщает её ошибки с кодом `1`.

Автообнаружение библиотек различает отсутствие каталога и ошибку пути. Повреждённая
ссылка, файл вместо каталога или отказ доступа к `PROWL_HOME/rules` либо
`PROWL_HOME/verifiers` дают ошибку загрузки, без перехода к другой библиотеке.
Правильные ссылки на каталоги поддерживаются. Явные `--rules-dir`/`--verifiers`
имеют приоритет; `--rules-only` не проверяет невыбранную установленную библиотеку.
`verifiers list` возвращает `2` при ошибках набора, а `verifiers validate` — `1`.

`bucket` и `repo` сохраняют относительные пути `--output`, `--config`, `--baseline`
и `--write-baseline` относительно каталога запуска. Настройки оператора загружаются
до скачивания; конфигурация и автоматический baseline из скачанной папки не читаются.
Пути bucket-находок имеют вид `s3://bucket/prefix/file` или `gs://bucket/prefix/file`
и сохраняют идентичность между скачиваниями. При сбое sync доступные объекты
сканируются с `source_error`, `truncated: true` и кодом `2`; baseline создать нельзя.
Ошибки клонирования также входят в неполный отчёт. Режимы Git для `repo` обращаются
к checkout напрямую, без смены рабочей директории процесса.

Скачивание bucket проверяет размер папки во время sync и после завершения команды.
Ошибка итогового обхода и превышение лимита блокируют результат без повторного
скачивания. Диагностический stdout/stderr внешних команд ограничен 64 КиБ.
На Unix отмена останавливает группу процессов, созданную для cloud CLI или Git clone;
ожидание унаследованных stdout/stderr ограничено одной секундой.

`mobile` проверяет фактический размер и CRC каждой читаемой ZIP-записи. Превышение
`--max-size`, лимита 64 МиБ на запись, 1 ГиБ суммарного извлечения или 200 000 записей
даёт неполный отчёт и код `2`; baseline из него создать нельзя. Исключённые записи
и медиафайлы не расходуют лимит извлечённых байтов. Длинные ASCII/UTF-16LE строки
сканируются целиком; `--no-strings` отключает бинарный проход и для файлов с текстовым
расширением, если их содержимое оказалось бинарным. Скачивание APK/IPA сверх лимита
также возвращает ошибку, вместо передачи усечённого файла на сканирование.

`image` сохраняет находки из доступных образов и слоёв при ошибках чтения остальных.
Повреждённый TAR или gzip trailer, превышение размера выбранного файла/config-поля
либо лимита распаковки дают неполный отчёт и код `2`, блокируя создание baseline.
Метаданные локального docker-save ограничены 64 МиБ на файл. Все записи manifest
сканируются отдельно, включая образы без тегов или с одинаковыми тегами. Отмена
прерывает ожидание stdin. При неполном обходе `in_final_image` остаётся неизвестным;
whiteout и замена каталога файлом учитываются при полном обходе слоёв.
Диагностику неполного сканирования не ограничивает `--max-per-file`.

Для локального OCI-layout метаданные ограничены 64 МиБ на файл и 128 МиБ суммарно;
вложенные индексы обходятся до глубины 32 с общим лимитом 1000 дескрипторов. Цикл,
сбой чтения или превышение лимита сохраняют находки доступных образов в неполном
отчёте и блокируют baseline. Общие подындексы обходятся один раз. При повторении
пути внутри TAR-слоя `in_final_image` учитывает конкретную запись; дедупликация
сохраняет версию, которая присутствует в итоговом образе.

HTTP API принимает ровно одно JSON-значение: объект для `/scan`, массив объектов для
`/scan/batch`. У каждого объекта обязателен строковый `content` (пустая строка допустима);
`source` и `path` — необязательные строки. Повтор поля, включая варианты регистра и
экранирования имени, повреждённый UTF-8 или непарный Unicode-surrogate возвращают `400`.
Размер ограничивается для всего тела, включая данные после JSON; превышение даёт `413`.
Ответ содержит `truncated`, а метрика `scanned` учитывает обработанные элементы:
пропущенные из-за размера или лимита ответа элементы в неё не входят.

## Конфигурация - `.prowl.yaml` (авто-обнаружение или `--config`)

Автообнаружение выбирает первый существующий файл: `.prowl.yaml`, `.prowl.yml`, затем
`prowl.yaml`. Ошибка выбранного файла останавливает команду с кодом `2` до получения
источника; перехода к следующему файлу или к дефолтам нет. Конфигурация содержит один
YAML-документ (пустые завершающие документы допустимы). Лимит чтения — 8 МиБ; специальные
файлы, включая FIFO, отклоняются. Для внешней taxonomy/gitleaks действует лимит 16 МиБ
и такое же требование обычного файла.

LSP использует эту же политику и автоматически импортирует `.gitleaks.toml` либо
`gitleaks.toml` из каталога запуска, включая allowlist. `detectors.enable/disable`
применяются после импорта; ошибка импортированного набора блокирует запуск редакторного
сканера. Запускайте LSP из каталога нужного проекта.

```yaml
version: 1
exclude: ["node_modules", ".min.", "vendor"]
detectors:
  disable: [generic_high_entropy]                  # выключить шумные
  custom:                                           # свои детекторы (как gitleaks)
    - {id: acme_token, regex: 'acme_[A-Za-z0-9]{20}', category: vcs}
allowlist:
  paths:   ["**/test/**"]                           # substring-match по пути
  values:  ["AKIAIOSFODNN7EXAMPLE"]                 # конкретные значения
  regexes: ['(?i)example|dummy']
output:  {format: sarif, fail_on: high, redact: true}
performance:
  max_size: 10485760            # макс. размер файла
  workers: 0                    # 0 = по числу CPU
  verify_concurrency: 8         # параллельных live-verify запросов
  verify_timeout: 8s            # таймаут одного verifier'а
  ml_threshold: 0.3             # порог ML-фильтра (--ml-threshold переопределяет)
detection:                      # пороги детекции (0 = встроенный дефолт)
  generic_entropy_min: 3.5      # мин. энтропия для generic_high_entropy
  placeholder_max_entropy: 4.2  # ниже - значение с placeholder-словом считается заглушкой
  max_matches_per_file: 50000   # DoS-кап на число матчей в одном файле
limits:                         # операционные лимиты (0/"" = дефолт)
  org_max_pages: 200            # макс. страниц API при обходе org/группы
  clone_timeout: 5m             # таймаут git clone для repo/org-сканов
```
Все значения опциональны; пропущенное/нулевое берёт встроенный дефолт. Где есть одноимённый флаг
(`--ml-threshold`, `--max-size`, `--workers`), он переопределяет config. Inline-подавление в коде:
`API_KEY = "..."  # prowl:allow` (совместимо с `pragma: allowlist secret`).

`prowl org` сохраняет частичные находки при сбое API или клонирования, но возвращает `2` и
`truncated: true`. Лимит страниц API также означает неполный обход; baseline для него не создаётся.
Пути и fingerprints включают clone URL без credentials и `.git`, поэтому не зависят от временного
каталога и различают одинаковые имена файлов на разных forge. Старый org-baseline может потребовать
обновления после полного сканирования. Подробнее: [обход организаций](../wiki/Org-Scanning.md).

## CI/CD (шаблоны в `ci/`)
- **GitHub Actions**: `ci/github-workflow.yml` (или `uses: Lercas/prowl@v1` через `action.yml`); SARIF в Security tab.
- **GitLab CI**: `ci/gitlab-ci.yml` (артефакт SAST).
- **pre-commit**: корневой `.pre-commit-hooks.yaml` (`id: prowl`, читает Git index, включая partial staging; bundled rules и reconstruction).
- **Docker**: `Dockerfile` (Debian slim, git и CA, UID 65532). Exit-код 1 при находках ≥ `--fail-on`.
  GitHub Docker Actions используют root `Dockerfile` либо `tool/Dockerfile.action`; при запуске от root сканер работает с UID и GID владельца workspace, чтобы приватный SARIF был доступен владельцу.

## Реализовано
- **Каскад L0+L1**: regex по таксономии + **checksum** (GitHub CRC32), структурная проверка JWT + entropy-гейт +
  **отсев example/placeholder** + **base64-размаскировка** (секреты внутри base64-блобов).
- **Источники**: filesystem (concurrent; recursive ZIP/JAR/TAR/GZIP + DOCX/XLSX/PPTX +
  PDF text layer + EML/EMLX/MBOX с декодированием MIME-вложений; опциональный локальный
  `--ocr` для PNG/JPEG/WebP и страниц PDF без текстового слоя),
  **git** (staged/since/history, включая архивы), **CI/CD** (GitHub Actions /
  GitLab CI logs + рекурсивно распакованные ZIP-артефакты), **domain** (HTML +
  `__NEXT_DATA__`/`__NUXT__`/`__INITIAL_STATE__`/... state-блобы с декодом escape'ов + referenced JS +
  source-maps; опц. crt.sh+wayback), **mobile** (APK/IPA как ZIP: ресурсы/JSON/plist/XML - в т.ч.
  `google-services.json`/`GoogleService-Info.plist` с Google API-ключами + project id - сканируются сырыми;
  бинарные entry `.dex`/`resources.arsc`/`.so`/Mach-O проходят чисто-Go printable-strings - 8-bit ASCII +
  UTF-16LE - так ключи из string-таблиц всплывают; флаги `--no-strings`, `--min-run N` + все scan-флаги; без Android SDK),
  **LSP** (didOpen/didChange дают diagnostics).
- **MCP-сервер** (`prowl mcp`): Model Context Protocol по stdio (построчный JSON-RPC) - AI-агенты
  (Claude Code/Desktop, любой MCP-клиент) драйвят сканы как инструменты. Tools: `prowl_scan` (path),
  `prowl_domain` (target + обязательный `authorized:true`), `prowl_mobile` (apk/ipa), `prowl_repo`
  (git url), `prowl_cicd` (GitHub/GitLab target) - каждый возвращает JSON-конверт находок. Полный
  гайд для агентов - `AGENTS.md` в корне репо.
- **Post**: baseline-подавление, inline-pragma, allowlist (path/value/regex), dedup перекрытий.
- **L2 ML-фильтр** (`--ml`): встроенная sklearn HistGradientBoosting-модель (`model_binary.json`, go:embed,
  49 фич) отсеивает ложные срабатывания generic-детекторов. Переобучена на реальных hard-negatives с гейтом
  на held-out данных. Также подключается через sidecar (`--ml-url`) или внешним файлом (`--ml-model`).
  Sidecar получает исходные значения кандидатов и контекст; локальный endpoint сохраняет обработку
  на той же машине. Ответ ограничен 1 МиБ и требует числового `score` в `0..1` для каждого кандидата.
  Неполный, неоднозначный или повреждённый ответ сохраняет весь пакет находок с предупреждением
  (fail-open). Подтверждённые live-верификатором секреты, checksum и ключевые файлы ML не удаляет.
  Внешняя модель выбирается через `--ml-model`, затем `PROWL_HOME/model_binary.json`
  (по умолчанию `~/.prowl/model_binary.json`), затем встроенная модель. Ошибка выбранного файла,
  повреждённая ссылка или недоступный родитель блокируют запуск ML-сканирования с кодом `2`.
  Допускаются ссылки на обычные файлы; FIFO и специальные файлы отклоняются. Лимиты модели —
  16 МиБ, 4096 деревьев и 250 000 узлов. Порядок всех 49 признаков должен совпадать с extractor;
  обязательные числовые поля, однозначный JSON, флаги узлов и отсутствие циклов проверяются
  до начала сканирования.
  Preflight сохраняет один экземпляр модели на команду; workers используют этот же снимок,
  а итоговый порог берётся из конфигурации или `--ml-threshold`. Изменение файла во время
  получения источников не меняет активную модель. Следующая команда загружает обновлённый файл.
- **Live-верификация** (`--verify`): набор верификаторов проверяет ключи через read-only identity-эндпоинты провайдеров.
  Кэш различает verifier и извлечённые реквизиты; одинаковые параллельные проверки делят запрос.
  Сетевые ошибки, HTTP 5xx и неполный ответ (лимит 64 КиБ) оставляют результат неопределённым.
  Ошибочная библиотека блокирует сканирование до получения источника: проверяются весь YAML,
  известные поля, уникальность ID и корректность матчеров. Лимиты — 512 КиБ на YAML,
  8 МиБ на manifest, 64 МиБ YAML и 10 000 файлов на каталог. Checksum и компиляция
  используют один снимок байтов; FIFO и ссылки за пределы выбранного каталога отклоняются.
  Частично повреждённый набор verifier’ов останавливает scan с кодом `2` до получения источника.
- **Verified blast radius** (`--verify`): live-находка сообщает, ЧТО ключ открывает, а не только live/dead -
  verifier объявляет `capability`-пробы, и rationale читается как «verified live: Google API key - unlocks:
  Firebase Identity Toolkit, Maps Geocoding». В комплекте `google-api-key`-verifier (Identity Toolkit / Gemini / Maps).
- **Меньше ложных срабатываний**: generic-детекторы (`generic_high_entropy`, `generic_password`,
  `generic_api_key`, `basic_auth_header`) отсеивают code module-пути, фрагменты минифицированного JS,
  license-key-формы, `\uXXXX`-юникод-строки, hash-дайджесты и URL-парсящие regex'ы - сохраняя реальные секреты
  (кавычные пароли, backslash-DSN, ключи без цифр). ML-стейдж (`--ml`) теперь скорит и плотные минифицированные
  бандлы. Private-key-детектор требует тела ключа (одинокий PEM-заголовок больше не срабатывает).
- **Вывод**: pretty / JSON / **SARIF 2.1** / **DefectDojo**; severity по категории; **redaction**; exit-gate; `--output` в файл.
- **Конфиг**: `.prowl.yaml` (exclude/disable/custom/allowlist/output/performance). Self-contained бинарь.

## Экспериментальный энкодер
L2 (HGB) уже работает как фильтр кандидатов. Опубликованный трансформер-энкодер
([`Podric/prowl-secret-encoder`](https://huggingface.co/Podric/prowl-secret-encoder)) — отдельная
research/integration-модель, которую можно подключить через собственный sidecar scorer; бинарник не
запускает её автоматически как третий этап. Точный контракт описан в `MODEL_INTEGRATION.md`.
